# Phase 7 Plan 02: AI Roadmap Generation Service

## Objective
Implement the core AI logic to generate personalized learning roadmaps for students based on their current skill sets and target professional roles.

## Proposed Changes

### 1. AI Utility (`src/lib/ai/roadmap.ts`)
Create a new utility `generateRoadmap` that:
- Accepts `studentId`, `currentSkills`, and `targetRole`.
- Constructs a detailed prompt for OpenAI's `gpt-4o-mini`.
- Uses structured output (JSON) to define 5-7 actionable roadmap steps.
- Each step should include a `title`, `description`, and potentially link to an existing `skill_id`.

### 2. Server Action (`src/app/dashboard/student/_actions.ts`)
Implement `generateAndSaveRoadmap`:
- Fetches student's current skills from the DB.
- Calls the `generateRoadmap` AI utility.
- Saves the resulting roadmap and its steps to the database in a single transaction.
- Returns the created roadmap object.

### 3. Verification Logic
- **AI Output Validation**: Ensure the generated JSON matches the expected schema.
- **Transaction Integrity**: Verify that either both the roadmap and all steps are saved, or neither is.

## Step-by-Step Execution Plan

1. **Step 1: AI Utility Implementation**
    - Create `src/lib/ai/roadmap.ts`.
    - Implement the prompt logic and structured extraction.
    - Ensure it handles edge cases (e.g., no skills found).

2. **Step 2: Server Action Implementation**
    - Add `generateAndSaveRoadmap` to `src/app/dashboard/student/_actions.ts`.
    - Implement the database transaction using `db.transaction`.

3. **Step 3: Verification**
    - Create a temporary test script to call `generateAndSaveRoadmap` and verify the DB state.

## Success Criteria
1. `generateRoadmap` returns structured JSON for a wide range of target roles.
2. `generateAndSaveRoadmap` correctly persists data to `roadmaps` and `roadmap_steps` tables.
3. Roadmap generation takes < 15s.
