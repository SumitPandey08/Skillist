# Phase 8 Plan 01: Mock Interview Data Layer & Session Management

## Objective
Establish the database schema and server-side infrastructure to manage mock interview sessions and their conversation history.

## Proposed Changes

### 1. Database Schema (`src/db/schema.ts`)
Add a new table `interviewMessages` to store each turn of the conversation:
- `id`: Unique identifier (nanoid).
- `interviewId`: Link to `mockInterviews`.
- `role`: 'interviewer' or 'candidate'.
- `content`: The text of the question or answer.
- `createdAt`: Timestamp.

### 2. Server Actions (`src/app/dashboard/student/_actions.ts`)
Implement session management logic:
- `createMockInterview`: Initializes a new session for a specific role/job.
- `addInterviewMessage`: Saves a turn in the conversation.
- `completeMockInterview`: Marks the session as finished and triggers AI evaluation.

### 3. Verification Logic
- **Schema Migration**: Run `npm run db:push` to apply changes.
- **Relational Integrity**: Ensure messages are correctly linked and cascaded upon interview deletion.

## Step-by-Step Execution Plan

1. **Step 1: Schema Update**
    - Add `interviewMessages` table.
    - Define relations between `mockInterviews` and `interviewMessages`.

2. **Step 2: Database Migration**
    - Run `npm run db:push` to sync the local DB.

3. **Step 3: Server Actions Implementation**
    - Add the new interview management actions to `src/app/dashboard/student/_actions.ts`.

4. **Step 4: Verification**
    - Test the creation and message appending logic via a simple script.

## Success Criteria
1. `npm run db:push` succeeds.
2. `createMockInterview` returns a valid session ID.
3. `interviewMessages` correctly persist and are retrievable by `interviewId`.
